# Code of conduct

Agora welcomes contributors of all backgrounds and experience levels. This code applies to issues, pull requests, reviews, discussions, and other project spaces, including when representing Agora elsewhere.

## Expected behavior

- Treat people with respect. Critique ideas and code with specific evidence and constructive suggestions.
- Make room for questions, different perspectives, and people learning the domain.
- Respect people's names, pronouns, privacy, and boundaries.
- Acknowledge mistakes, accept reasonable feedback, and help resolve disagreements calmly.

## Unacceptable behavior

Harassment, discriminatory language, threats, sexual advances, personal attacks, doxxing, and deliberate intimidation are unacceptable. Do not publish another person's private information or use project spaces for spam. Repeated disruption after a moderator asks it to stop is also unacceptable.

Technical disagreement is welcome; abuse is not. These standards apply equally to contributors and maintainers.

## Reporting concerns

Use **Report content → Report to repository admins** on the relevant issue, pull request, or comment to notify maintainers privately. Repository content reporting is enabled. For a violation of GitHub's platform rules, or a concern involving the repository owner, choose **Report abuse to GitHub Support** instead. See [GitHub's reporting instructions](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).

If the concern has no reportable content and needs private discussion with a maintainer, open an issue titled **Request private maintainer contact**, without incident details or anyone's personal information, to arrange a private channel. You can also contact [GitHub Support](https://support.github.com/contact/report-abuse) directly about platform abuse. GitHub handles its platform reports; project maintainers handle repository moderation.

Do not post sensitive evidence publicly. Share only what is needed with the person reviewing the report. Security vulnerabilities use the separate [security policy](SECURITY.md).

## Moderation

Maintainers may edit or remove harmful content and restrict participation. Responses can include a request to stop, a warning, a temporary restriction, or a permanent ban, depending on severity and repetition. Serious threats or harassment can lead to immediate removal.

Maintainers should explain moderation decisions when safe, consider relevant context, avoid retaliation, and limit sharing of report details. Affected participants may request reconsideration through the same private reporting route. No one is required to confront the person they are reporting.
